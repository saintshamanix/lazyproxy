# Обновление до 3x-ui 3.9.0 через панель

[English](UPGRADE-3.9.0.md)

Сначала обновите один сервер с одним IP. После проверки на устройстве — сервер
с двумя IP. Используйте штатное обновление в веб-панели и проверьте, что предлагается
стабильная **3.9.0**. Более новая версия не входит в проверяемую границу адаптера.
LazyProxy не выполняет это обновление панели.

## До обновления

- Сделайте снимок у хостера, желательно при остановленном VPS, и скачайте копию
  базы из панели. Старые бинарники панели/ядра и базу храните совместно.
- Для восстановления нужны `/etc/x-ui`, `/usr/local/x-ui`, `/etc/single443`,
  `/opt/single443`, nginx, Netplan, сертификаты, systemd units и drop-ins.
  Экспорт базы не восстанавливает реверс-прокси и ожидание второго IP при загрузке.
- Зафиксируйте ID входящих, число клиентов, адреса подписок, свои правила
  маршрутизации и адреса прослушивания. Не публикуйте ключи и резервные копии.
- Не запускайте установщик/обновление LazyProxy одновременно с обновлением панели.

## Во время обновления

При перезапуске x-ui соединения прервутся. Штатный обновляющий скрипт может сообщить,
что у самой панели нет сертификата: в нашей схеме TLS завершается на nginx.
Если появится выбор, используйте **Skip SSL / behind reverse proxy**, сохранив
`127.0.0.1:2053` и существующий путь панели. Не выпускайте новый сертификат
и не меняйте порт. Если веб-обновление зависло на интерактивном вопросе, проверьте
его статус/журнал через SSH; не запускайте повторные обновления вслепую.
Открывайте прежнюю публичную HTTPS-ссылку, а не внутренний HTTP-адрес из вывода.

3.9.0 автоматически мигрирует базу и исходящие WireGuard. При сбое миграции
нельзя считать запуск старого бинарника поверх новой базы полноценным откатом:
восстановите снимок или совместную копию старой базы и бинарников.
Для кластера сначала обновите все узлы, затем включайте недельное продление.

## Один и два IP

| Схема | Hysteria2 | AmneziaWG |
|---|---|---|
| Один публичный IP | UDP/443 | UDP/51820 |
| Два публичных IPv4 | основной IPv4:443/UDP | дополнительный IPv4:443/UDP |

Сохраните Netplan, nginx, nftables и `single443-addresses.conf`.
Повторно запускать `attach-secondary-ip.sh` на уже перенесённом сервере не нужно.
В схеме с двумя IP оба UDP/443 должны слушать конкретные адреса, без wildcard.
У пустого AWG-входящего сокет может отсутствовать до добавления первого клиента.

## После обновления

```bash
sudo /usr/local/x-ui/x-ui -v
sudo systemctl is-active x-ui nginx single443-firewall
ip -br address
sudo ss -lnup
sudo nginx -t
sudo nft list table inet single443
sudo systemctl cat x-ui
sudo journalctl -u x-ui --since "10 minutes ago" --no-pager
```

Проверьте вход в панель, сохранность клиентов, обновление подписок, реальный трафик
через используемые протоколы, WARP/свои исходящие и оба UDP-адреса с внешней сети.
Пинг в панели и наличие сокета не доказывают прохождение аутентифицированного handshake.
Для WARP на сервере без рабочего IPv6 проверьте после миграции
`streamSettings.sockopt.domainStrategy`, сохранив ключи и адреса внутри туннеля.

Обновление панели не обновляет `/opt/single443`. Если позднее потребуется обновить
компоненты LazyProxy, берите `--update-only` из **актуального репозитория**, а не
старой закреплённой копии. Скрипт читает реальную версию бинарника и синхронизирует
состояние установщика внутри транзакции с резервным копированием/откатом.
Второй IP сохраняется, бинарники панели не обновляются и не понижаются.
Этот шаг необязателен; он также обновляет управляемые сайт и файлы маршрутизации.

## Изменения совместимости

`inbounds/update` сохраняет клиентов и флаг включения входящего. Для старой миграции
подписок LazyProxy использует клиентский API; изменение входящих касается только
транспорта, отображения и адресов. Пересекающиеся диапазоны клиентов AWG могут
помешать редактированию в 3.9.0: корректируйте их индивидуально. Не путайте диапазоны
отдельных серверных peers с `allowedIPs` исходящего WireGuard для всего трафика.
