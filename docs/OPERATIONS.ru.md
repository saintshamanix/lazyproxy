## Домены и IP TLS

| Режим | Условия |
|---|---|
| Автодомены | `IP.cdn-one.org` и `IP-с-дефисами.cdn-one.org` разрешаются в IP VPS |
| Собственные домены | Оба параметра `--domain` и `--reality-domain`; разные имена, прямые A-записи, без CDN-прокси, AAAA и CNAME |
| IP TLS | `--ip-tls` на чистом VPS; несовместим с параметрами собственных доменов |

Указывайте DNS-имена без схемы, портов и путей; международные — в Punycode.
TCP/80 должен оставаться доступным для ACME.
Файл root `--config /root/lazyproxy.env` может задавать те же параметры и переопределяет CLI.
См. [config.example.env](../config.example.env), включая параметр версии панели.

Повторный запуск сохраняет домены и режим TLS. Смена основного IP, доменов или режима TLS требует отдельной миграции.

IP TLS использует публичный IPv4 для веб-сервисов и TLS-подключений, но сохраняет автодомен REALITY.
Сертификат содержит IP и DNS SAN; проверка сертификатов включена.
IP-сертификаты используют профиль `shortlived` (160 часов).
Отдельный Certbot 5.8.0 установлен в `/opt/single443-certbot-5.8.0`, состояние ACME — в `/etc/single443/acme`.

`single443-acme.timer` проверяет продление каждые шесть часов.
После продления выполняются проверка/reload nginx и restart x-ui для Hysteria2;
неудачная перезагрузка повторяется при следующей успешной проверке.
Диагностика требует минимум 24 часа до истечения сертификата.

```bash
sudo systemctl list-timers single443-acme.timer
sudo journalctl -u single443-acme.service --no-pager -n 50
```

Источники: [IP-сертификаты Let's Encrypt](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability/),
[поддержка Certbot](https://letsencrypt.org/2026/03/11/shorter-certs-certbot/).

<a id="second-ipv4"></a>
## Второй IPv4

Сначала настройте дополнительный публичный IPv4 в Ubuntu с сохранением после перезагрузки и проверьте доступность.
Затем из распакованной актуальной копии LazyProxy выполните:

```bash
sudo bash attach-secondary-ip.sh SECOND_IPV4
```

Скрипт создаёт резервную копию, привязывает Hysteria2 к IP1:443/UDP и AmneziaWG к IP2:443/UDP,
закрывает UDP/51820 и перезапускает панель.
Клиенты, ключи и маршрутизация сохраняются; при ошибке выполняется откат.
Оба UDP-входящих становятся IPv4-only. UFW должен оставаться выключенным.

Скачайте новые конфигурации AWG и проверьте оба протокола извне.
IP2 меняет точку входа, но не исходящую маршрутизацию и IP выхода.
Обновления сохраняют разделение; после обновления панели повторная привязка IP2 не нужна.

<a id="lazyproxy-update"></a>
## Обновление LazyProxy

Для обновления обвязки используйте [команду установки из README](../README.ru.md#установка), заменив только финальный вызов:

```bash
bash "$f" --update-only
```

Команда загружает актуальный репозиторий, создаёт резервную копию и обновляет управляемые компоненты, включая сайт и файлы маршрутизации.
Версия работающей панели определяется автоматически; сама 3x-ui не обновляется и не откатывается.
Для неё используйте [обновление через панель](UPGRADE-3.9.0.ru.md).

Ручные имена и лимиты клиентов сохраняются. Старые имена `single443-*` мигрируют в `UserN`.
Отсутствие/неоднозначность управляемых записей или несовместимые ручные изменения останавливают обновление.
Если меняли режим XHTTP, сначала верните `stream-up`.
Дождитесь `Updated.`, затем обновите подписки клиентов.

## Диагностика и ограничения

```bash
sudo bash /opt/single443/diagnose.sh
sudo nginx -t
sudo journalctl -u x-ui --since "10 minutes ago" --no-pager
```

- Журнал: `/var/log/single443/install.log`; резервные копии: `/var/backups/single443/`.
- Upstream XHTTP: `grpc_pass grpc://127.0.0.1:10002;`. HTTP/3 на nginx в этой схеме отсутствует.
- У включённого AWG без клиентов может не быть UDP-сокета.
- Импорт AWG `vpn://` в Shadowrocket не гарантирован. Старые native-экспорты: `/etc/single443/User6-AmneziaWG.conf`.
- IP-лимит клиентов по умолчанию — `0`. Его применение за nginx требует передачи реального IP; одного Fail2ban недостаточно.
- Профиль INCY требует проверки в клиенте; placeholders Clash/Mihomo не являются готовой политикой маршрутизации.
- WS/gRPC доступны; предупреждения upstream об устаревании сохраняются.

## Обслуживание

Таймер проверяет срок ежечасно и запускает очистку через 72 часа после последнего успешного выполнения, в том числе после простоя.
Очищаются активные журналы nginx с сохранением архивов, ротируется/очищается journal
(`--vacuum-time=1d --vacuum-size=10M`), выполняется `apt-get clean`.
Активные файлы journal могут превышать 10 МиБ; это не постоянный лимит размера.

Удаление пакетов по умолчанию выключено. `AUTO_REMOVE=yes` в `/etc/single443/maintenance.env`
включает `apt-get autoremove --purge -y`.
При ошибке очистка повторяется через час; выполненную очистку откатить нельзя.

```bash
systemctl list-timers single443-maintenance.timer
journalctl -u single443-maintenance.service
```
